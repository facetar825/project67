# QuestDesk — система квестов

Готовая проектная работа № 2: настольное приложение с бизнес-логикой и PostgreSQL.
Тема: «Система квестов». Интерфейс на русском языке.

## Быстрый запуск на Windows

1. Откройте `dist/QuestDesk/QuestDesk.exe` двойным щелчком.
2. При первом запуске подождите: приложение подготовит локальную PostgreSQL,
   создаст базу, восемь таблиц и осмысленные начальные данные.
3. На экране «Обзор» откройте первый квест. Отметьте три шага и нажмите
   «Завершить и получить награду». Начислится 140 XP и 50 монет.
4. Откройте «Награды» и получите «Час любимой игры» за 30 монет.
5. Проверьте остаток 20 монет, прогресс навыков и записи в истории.

В комплекте есть Python runtime и PostgreSQL. Устанавливать Python,
создавать таблицы вручную и подключаться к интернету для готовой сборки не нужно.
**Переносите всю папку `dist/QuestDesk`, а не только файл exe.**
Поддерживается Windows x64. Сборка проверена на Windows 11.

Личные данные находятся в `%LOCALAPPDATA%/QuestDesk/pgdata`, настройки подключения
в `%LOCALAPPDATA%/QuestDesk/connection.json`, логи — `app.log` и `postgres.log`
в той же папке. В исходниках и архиве нет пароля пользователя или его данных.
Обновление/перенос папки программы не удаляет прогресс.
Сама БД между компьютерами автоматически не переносится: используйте pg_dump/pg_restore.

Сервер принимает подключения только с этого компьютера, порт `55439`.
Пароль генерируется при первом запуске, используется SCRAM-SHA-256.
Служба Windows не устанавливается. После закрытия программы PostgreSQL остаётся
в фоне, чтобы второе окно и повторный запуск могли использовать ту же базу.
Для остановки закройте окна приложения и выполните `scripts/stop-postgres.ps1`.

## Что реализовано

- Обзор состояния: имя, уровень, опыт, монеты, число активных квестов и рекомендация.
- Квесты: создание, просмотр, поиск, фильтрация, изменение планов и удаление.
- Карточка квеста: описание, срок, сложность, навыки, интерактивные шаги.
- Состояния: запланирован → в работе → завершён / не выполнен.
- Опыт и монеты начисляются один раз, только за полностью выполненный квест.
- Справочники навыков и наград: создание, просмотр, редактирование, удаление.
- Покупка наград с проверкой баланса и неизменяемым снимком названия и стоимости.
- Обработка просрочки при входе, переходах, обновлении и раз в минуту.
- История действий; JSONB хранит детали начисления, списания и причину штрафа.
- Защита от повторного начисления и перерасхода при параллельных действиях.

## Правила

Лёгкий квест: 40 XP и 15 монет. Обычный: 80 XP и 30 монет.
Сложный: 140 XP и 50 монет. Уровень = `1 + XP // 200`.
Каждый связанный навык получает полный опыт завершённого квеста.
Можно выбрать несколько навыков или не выбирать ни одного.

Редактируются только запланированные квесты: после начала нельзя увеличить
награду или заменить уже выполненные шаги. Активный квест нельзя удалить:
сначала завершите его или откажитесь. Отказ и просрочка снимают до 10 монет;
баланс не становится отрицательным. Опыт не отнимается.
Дата срока включительна. Просрочкой считается дата раньше текущей локальной даты.
Запланированный просроченный квест не штрафуется: перед началом измените срок.

Удаление завершённого квеста сохраняет заработанный опыт, баланс и историю.
Навык со связями удалить нельзя. При удалении награды история покупок сохраняется.
Повторная покупка одной награды разрешена при достаточном балансе.

## Архитектура и файлы

- `app.py` — настольный интерфейс Tkinter/ttk, формы и навигация.
- `domain.py` — правила валидации, начисления и уровней.
- `service.py` — бизнес-операции, транзакции, порядок блокировок и история.
- `db.py` — подключение, запросы и однократная инициализация базы.
- `bootstrap.py` — изолированный локальный сервер PostgreSQL.
- `database/schema.sql` — DDL, ограничения, ENUM и индексы.
- `database/seed.sql` — четыре квеста, десять шагов, три навыка и три награды.
- `docs/architecture.md` — схема связей и объяснение архитектуры.
- `docs/defense.md` — речь, сценарий демонстрации и ответы на вопросы.
- `output/pdf/QuestDesk_Report.pdf` — отчёт для сдачи.
- `tests/` — модульные и интеграционные проверки.
- `scripts/` — сборка, загрузка PostgreSQL и остановка сервера.

## Запуск из исходников

Требуется Python 3.12+ с Tkinter. Команды выполняются из папки проекта:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe app.py
```

Если папка `vendor/pgsql` отсутствует, предварительно выполните:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/setup-postgres.ps1
```

Для собственной PostgreSQL создайте пустую БД и задайте строку подключения:

```powershell
$env:QUESTDESK_DSN = 'host=localhost port=5432 dbname=questdesk user=YOUR_USER password=YOUR_PASSWORD'
python app.py
```

При внешнем подключении приложение не запускает локальный сервер.
Пользователю PostgreSQL нужны права создавать таблицы, типы и индексы в public.
Используйте отдельную пустую БД: инициализация рассчитана на схему QuestDesk 1.0.
Секреты не размещайте в Git. Для альтернативного расположения локальных данных
используйте `QUESTDESK_HOME`; для портативного PostgreSQL выбирайте путь латиницей.

## Тестирование

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Интеграционные тесты используют настоящую PostgreSQL, создают отдельные базы
`questdesk_test_<uuid>` и удаляют только эти базы. Рабочая база не очищается.
Для внешнего сервера задайте `QUESTDESK_TEST_DSN`; его пользователю необходим CREATEDB.
Модульные тесты отдельно: `python -m pytest tests/test_domain.py -q`.

Проверяются CRUD, связи, валидация, SQL-инъекция, ограничения БД, обработка просрочек,
недостаток средств, сохранение истории и конкурирующие завершения/покупки.
Результат выполненного прогона: 20 тестов пройдены.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build.ps1 -Python .venv\Scripts\python.exe
```

## Границы учебного проекта

Один локальный профиль без регистрации; многопользовательская авторизация не входит
в эту версию. Приложение не предназначено для публикации PostgreSQL в интернет.
Нет фонового планировщика при закрытом приложении: просрочки обработаются при следующем
открытии. Каталог начальных квестов появляется только в новой базе.
Представление SQL-ошибок отделено от сообщений пользователю; детали сохраняются в лог.
